How it fits

A real transformer, written in assembly for the Game Boy's 8-bit CPU. The words on the screen are computed there, one token at a time. You're watching it in an emulator, and it has never been tested on a physical console.

The model

One transformer block with two attention heads, 32-dimensional embeddings and a 64-unit feed-forward layer. It looks at up to 32 tokens at once, from a vocabulary of 763 words and short phrases.

A full output layer would be too big, so it goes through a 16-unit bottleneck first. It was trained on a computer against a dialogue corpus written for this character. The console only runs it, and the weights never change during play.

Numbers

The CPU has no floating point, so weights and activations are 8-bit integers. Training simulated that rounding, so the model learned to work with it. A separate Python reference does the same integer math, and the tests require the ROM to match it token for token.

Memory

The console has 8 KB of built-in work RAM, and this ROM uses 5,303 bytes of it. That covers the attention cache, activations, scores for every token and the game itself. The weights stay in the 128 KB ROM.

The cartridge adds 32 KB of battery-backed RAM. One 8 KB bank holds speed-up tables, and a much smaller part holds your save. That save is why it remembers your name: it stores facts and counters in ordinary game memory, and the model reads a summary of them. It isn't learning.

From your keyboard to the chip

  1. The page puts your text in the ROM's input buffer, the same one its on-screen keyboard fills, and presses Start. The four quick buttons send ready-made phrases the same way.
  2. A parser in assembly picks out keywords and turns them into an intent and a topic. Unknown words get an admission that it didn't understand.
  3. The game adds its mood, what it thinks of you and what it remembers, making a 9-token prompt.
  4. The model reads that prompt and starts writing.

That parser is the reason it can't hold a general conversation. The model sees only that summary, never your actual sentence, and it knows a handful of topics.

Writing one token

Each step runs attention over the tokens so far, reusing cached results for the earlier ones. It then scores every allowed token, marks down words it has already used, and draws from the closest candidates using the ROM's own random numbers. The first token picks the robot's face, and every token after that is a word or punctuation.

A token takes about 0.96 seconds, and an average reply takes about 13.5 seconds. Replies mostly recombine sentences people wrote, which is what a model this small can do reliably.

Why this is hard

The CPU has no multiply instruction. A transformer is mostly multiplication, and each one has to be built by hand from shifts and adds. The registers are 8 bits wide, the ROM can only show a small window of itself at a time, and the screen and animation still need attention every frame so the game doesn't freeze while it thinks.

Caching attention made it about twice as fast on its own. A table-based multiply gave about 1.75 times, and per-token multiplication tables in cartridge RAM added about 1.29 times on top of the rest. All the work together makes it about ten times faster, with identical output. You can race both versions yourself.
