# Results

Generated by `tools/compare.py` from raw reports. Do not edit by hand. Timing is on an emulated original Game Boy (DMG), not physical hardware.

**Shipping build:** V5Z + zero-column skip. ROM SHA-256 `03db35f59af2c28fd42db7dbc09d5fafe0ba359a77730e2f39e67e92a19fd300`, 65536 bytes, MBC5, no SRAM.
**Model:** 1-layer causal transformer, d=32, 2 heads, FFN 64, context 24, vocabulary 196, 21504 int8 parameters. Blob SHA-256 `dd7e1c8f5e293a267bbcab1b43603293f7461a8df338b5969e0a72582628ab69`.
**Emulator:** PyBoy 2.9.0 with `cgb=False`, 4,194,304 Hz nominal. Commit at measurement: `cb21873`.

**Speedup: 9.69x, with identical tokens on all four workloads.** Same model, same weights, same prompts, same greedy decoding.

**How much of that is the baseline's choice?** V0 recomputes every key and value for every token, which a port aimed at speed wouldn't do. Against V0 with only the K/V cache added, V5Z is 4.16x faster. That's the fairer figure for the kernel work alone.

### Timing calibration

`tests/test_smoke.py` runs a known instruction sequence and asserts PyBoy's counter between two hooks equals the hand-counted 112 T-cycles from Pan Docs timings. SameBoy has no equivalent counter in this setup: its check is the ROM's own LCD-frame counts above, which match PyBoy's exactly.

PyBoy's memory reads don't model PPU access locks, so VRAM comparisons in the tests can't detect a PPU-mode violation. The self-test screens read back from SameBoy cover that for the screens they draw, but not every game screen.

## Model quality

All figures are on the integer reference, which the ROM matches bit for bit. Training: 20000 float then 12000 QAT steps.

- **Shipping model** (trained on every reachable situation): validation NLL 0.0082 nats/token. Uniform over the vocabulary: 5.2781. Untrained model: 5.9171.
- **Sibling model** with situations held out, used only to measure generalization and never shipped: see the table.

Strict valid means the text is an exact member of the grammar for that situation. Plot and sentence content are authored: the model learned them, and it doesn't invent story. The 100% on situations it trained on shows it learned the language; the sibling row shows what happens on unseen combinations of a known event and known items.

**Conditioning.** Changing only the event token changes the greedy text 100.0% of the time over 210 situations. Changing only the carried items, on the same event, changes it 42.5% of the time over 200 pairs. That is lower because only the lamp and friend change the wording.

**Sparsity.** On the integer reference across all 210 situations, 58.1% of feed-forward activations are exactly zero after ReLU, which is what V5Z exploits.

## Limitations

- Emulator only. No physical DMG has run this ROM. V5S and V5Z stream weights through SP with interrupts held off per row; V5 is the build to prefer if that is a concern on real hardware.
- **The plot is authored.** The story graph and the sentences the model trains on were written by hand. The model produces every word on screen, but it learned this language and doesn't invent new plot. Replays vary in wording, within what it learned.
- **Game truth lives in the deterministic engine.** The model narrates; it can't change state.
- **Omens are not independently scored.** The grammar always places the correct omen, and strict validity covers it, but no player study checked that people notice them.
- The model is small: it has learned a grammar, and this is not conversational AI.
- INT4 was studied on the reference only. V7 (ternary or codebook weights) and V8 (automatic configuration search) were not attempted.
