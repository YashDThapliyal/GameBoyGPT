# GameBoyGPT: 8-Bit Adventure

A branching adventure for the original 1989 Game Boy, where a tiny transformer running on the console's 8-bit CPU narrates the story as you play, one word at a time. There is no server, GPU or table of stored sentences: the attention, matrix math and sampling are all SM83 assembly.

![Emulator screenshot of the game](docs/figures/hero.png)

*Emulator screenshot (PyBoy, DMG mode). This has not been run on a physical Game Boy.*

![Real-time capture of the first turns](docs/figures/demo.gif)

You choose your way through three acts to one of eight endings. What you pick up changes what you can do later, and the narration warns you which choices are dangerous, if you read closely.

The project also asks a measurement question: **what actually makes neural text generation faster on a 4 MHz, 8-bit CPU with 8 KB of RAM?** Every optimization below was built separately, checked for identical output and timed in T-cycles.

## Play it

ROMs are in [`release/`](release/): `gameboygpt.gb` is the fast build and `gameboygpt_v0.gb` is the slow baseline. Open either in any Game Boy emulator set to DMG, or run `make play`.

| Button | Action |
|---|---|
| Up, down | Move the pointer between choices |
| A or START | Confirm, next |
| SELECT | Run stats, measured on the device |
| START on stats | New run |

In `make play`, the keys are the arrow keys, `A` or Enter to confirm, `S` for B and Backspace for SELECT. Text looks sharpest if you leave the window at its opening size.

Try to find all eight endings. See [docs/GAMEPLAY.md](docs/GAMEPLAY.md).

## How it works

```
You pick a choice -> story engine updates items, wounds and scene
                                              |
                  <BOS> EVENT ITEMS FATE                   symbolic prompt, 4 tokens
                                              |
                 1-layer transformer on the SM83           int8 weights in ROM
                 attention over all earlier tokens         K/V cache in WRAM
                                              |
                 next word, drawn immediately  <-- repeats until <EOS>
```

**Authored versus generated.** The plot is written by hand: the scenes, choices, consequences and endings in `reference/story.py`, and the language the model trains on in `training/dataset.py`. The model doesn't invent plot. It's told what just happened and produces every word of the narration, with varying wording between playthroughs. It can't change what happens, so it can't break the game. The display only adds capital letters.

See RESULTS.md for the exact model size, RAM and ROM use.

The architecture is in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), the equations in [docs/MODEL.md](docs/MODEL.md) and the rounding rules in [docs/NUMERICS.md](docs/NUMERICS.md). The long version of the story is [TECHNICAL_REPORT.md](TECHNICAL_REPORT.md).

## How you know it's real

- **Bit-exact reference.** `reference/fixed_point.py` is a separate implementation in plain Python integers. Each SM83 kernel, the masked logits and full token traces match it, for both greedy and sampled decoding.
- **Patching weights changes the story.** A test flips one row of output weights inside the ROM. The event changes to exactly what the reference predicts for the patched weights.
- **No stored sentences.** A test checks that the ROM's weights match the export byte for byte and that narration phrases don't exist in it as text.
- **Runs with no host.** The self-test ROM prints `SELFTEST PASS` and frame counts on its own screen, read back by matching pixels, with identical results on SameBoy and PyBoy.
- **Trustworthy clock.** The cycle counter matches a hand-counted instruction sequence, and the ROM's own LCD-frame timing agrees with it to within 0.1%.

## Reproduce it

You need [RGBDS](https://rgbds.gbdev.io/) and [uv](https://docs.astral.sh/uv/). Exact versions are in [toolchain.lock](toolchain.lock). This was run on macOS on Apple Silicon only; Linux is untested. To check the release independently, see [VERIFY.md](VERIFY.md) or run `scripts/verify_release.sh`.

```
uv sync --python 3.12
make all               # build every variant and run the tests
make second-emulator   # self-test on SameBoy and PyBoy (clones and builds SameBoy)
make benchmark         # cycle measurements
make demo              # scripted play; fails if any event differs from the reference
make report            # figures, RESULTS.md, memory map, dashboard
make train             # optional: retrain; reproduces generated/model.bin byte for byte
```

## Limitations

- **Emulator only.** No physical Game Boy has run this. The fastest build streams weights through the stack pointer with interrupts held off per row. It was designed to be safe on hardware and passes on SameBoy, but it's untested on silicon. The `V5` build avoids that trick; RESULTS.md has its speed.
- **An authored story in a narrow language.** The model learned a small hand-written language. It's a real language model of a very small language, and it isn't conversational or general. Its high validity reflects how narrow the task is, and replays differ in wording, not plot.
- **Generation takes seconds per passage.** That's playable, but it isn't instant.
- **Not attempted:** packed INT4 weights in ROM (studied on the reference only), ternary or codebook weights, automatic configuration search.

## Prior art

This is not the first language model on Game Boy hardware. [gbc-transformer](https://github.com/maddiedreese/gbc-transformer) runs a 260K-parameter TinyStories transformer on a Game Boy Color. [ChatGBC](https://github.com/crashtheuniverse/chatgbc) is a pure-assembly recurrent model. [Elyan Labs](https://www.elyanlabs.ai/gbc-llm.html) published a careful optimization study, and the `pop` weight stream here was prompted by their work. Their numbers come from different models and hardware, so they aren't compared here. What's distinct is the interactive game, the per-optimization ablation, and the bit-exact verification. See [docs/PRIOR_ART.md](docs/PRIOR_ART.md).
